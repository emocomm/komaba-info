## フィッツの法則とは

**フィッツの法則（Fitts's Law）** は、ある対象（ターゲット）に手やカーソルを動かして到達するのにかかる時間を予測する法則です。1954年に心理学者の Paul Fitts が提案しました。

直感的にはとても当たり前のことを言っています。

- ターゲットが **遠い** ほど、到達に時間がかかる
- ターゲットが **小さい** ほど、狙いを定めるのに時間がかかる

逆に言えば、**近くて大きいターゲットほど速く正確にクリックできる** ということです。マウスのカーソルでも、スマートフォンを触る指でも、この関係は安定して成り立ちます。

## 式で表すと

フィッツの法則は、到達時間 `T` を次の式で表します。

<div class="code-copy">
  <pre><code>T = a + b · log₂(D / W + 1)</code></pre>
  <button type="button" class="small" data-copy="T = a + b · log₂(D / W + 1)">コピー</button>
</div>

- `T`：ターゲットに到達するまでの時間
- `D`：スタート地点からターゲットまでの距離（Distance）
- `W`：ターゲットの幅（Width）。動く方向に沿った大きさ
- `a`・`b`：実験で求める定数（`a` は反応や準備にかかる時間、`b` は難しさ1単位あたりの増え方）

式の中の `log₂(D / W + 1)` の部分は、その動作の「難しさ」を表す量で、**困難指数（ID：Index of Difficulty）** と呼ばれ、単位は `bit` です。

<div class="code-copy">
  <pre><code>ID = log₂(D / W + 1)</code></pre>
  <button type="button" class="small" data-copy="ID = log₂(D / W + 1)">コピー</button>
</div>

つまりフィッツの法則は「**到達時間 T は、困難指数 ID に比例して増える**」という、`T = a + b · ID` の形の直線の関係だと読み替えられます。`D` が大きいほど、また `W` が小さいほど ID は大きくなり、クリックに時間がかかります。今回の実験では、`D` と `W` を変えながら `T` を測り、本当にこの直線の関係になるかを確かめます。

<div class="callout">
  <strong>なぜ単純な「距離 ÷ 大きさ」ではなく log なのか</strong><br>
  距離が2倍になっても到達時間は2倍にはならず、対数的にゆるやかにしか増えません。これは、人が目標に近づくと「大きく動かす → 少し戻す → 微調整する」と段階的に近づいていくためだと説明されます。情報量（エントロピー）と同じ <code>log₂</code> が現れるのは偶然ではなく、フィッツは「動作の難しさ＝処理すべき情報量」とみなしました。
</div>

## なぜこの法則が大事なのか

フィッツの法則が重要なのは、それが **使いやすいインターフェースを設計するための、数量的な指針** になるからです。「なんとなく押しやすい／押しにくい」を感覚で語るのではなく、**距離と大きさという測れる量** で説明し、設計に活かせます。

法則からは、設計上の具体的な原則が導けます。

- **よく使うボタンは大きくする** — `W` を大きくすれば ID が下がり、速く正確に押せる。重要な操作や、押し間違えると困る操作ほど大きく。
- **関係する操作は近くに置く** — `D` を小さくすれば到達が速い。続けて使うボタンを離して配置すると、その往復が積み重なって遅くなる。
- **画面の端と角は「実質的に無限の大きさ」になる** — カーソルは画面の外には出られないので、端に置いた要素は行きすぎる心配がなく、とても狙いやすい。macOSが画面最上部にメニューバーを置いたり、スタートボタンを角に置いたりするのはこのため。
- **操作の場所にメニューを呼び出す** — 右クリックメニューのように、いまカーソルがある場所にメニューを出せば `D ≈ 0` になり、移動がほぼ不要になる。
- **スマートフォンでは親指の届く範囲を意識する** — 指の届きやすさ（距離）と、タップ領域の大きさ（44px以上が目安）は、フィッツの法則そのもの。

このように、フィッツの法則は、Webサイト・アプリ・ゲーム・自動車の操作パネルなど、**人が何かを狙って操作するあらゆる場面** の設計判断を支えています。今回の演習で自分のデータからこの法則を確かめることは、ユーザインタフェース（UI）やユーザ体験（UX）の設計を、根拠をもって考えるための第一歩になります。
